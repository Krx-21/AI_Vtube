# C03-memory — Memory system
Verdict counts: {'disputed': 8, 'refuted': 6, 'likely': 11, 'unverifiable': 10, 'confirmed': 2}

## Summary A (evidence hunter)
The load-bearing conclusion this cluster inherited from the Lin-Guanguo community doc — "within-session context only, no confirmed persistent cross-session memory" — is refuted at T1 by Vedal's own words on the 9/10 June 2025 dev stream (youtube.com/watch?v=HbraxW11WSU): he describes shipping "changes to the long-term and short-term memory," states the goal that Neuro "shouldn't forget anything that happens in a stream," that "long-term you should be better at remembering important things and keeping that information for longer," that "this system comes with lower latency," and that what he is testing is "her ability to remember what happens in a stream, what happens over multiple streams." A discrete long-term memory system therefore exists and is explicitly cross-session by design; what remains genuinely undocumented is its implementation (no confirmed RAG, vector DB, summarizer, or consolidation step — the only official artifact that touches retention is the neuro-sdk spec's `ephemeral_context` flag, which states that non-ephemeral `state`/`query` context "will be remembered by Neuro after the actions force is completed"). The competing "memory is really just irregular offline fine-tuning" theory is refuted as an explanation of long-term memory: Vedal frames memory as a runtime subsystem with its own latency profile and never ties it to retraining, and NamuWiki reports him saying Evil Neuro's long-term memory held only three countable items around late 2024 with expansion planned — a small slot-based store, not an open-ended embedding index. Manual curation of training data is separately T1-confirmed, but from Vedal's January 2023 Kotaku interview ("Data that she learns on is also manually curated to mitigate negative biases"), i.e. it originated as a safety/bias fix, not a memory mechanism. Evidence for the dated upgrade events is weak and mostly negative-space: the "August 1 2024 short-term memory upgrade → Broken Record loops" story rests on one uncited wiki passage echoed by search-engine summaries, and the clip cited for it is dated May 2024; the June 2025 event is the only memory upgrade with a primary transcript. No verbatim, dated example of correct cross-session recall has ever been published, no end-of-stream consolidation process is described anywhere, catastrophic-forgetting handling is never discussed, and the effect of the April 2026 codebase rewrite (whose driver was Unity *memory leaks*, an unrelated sense of "memory") on the memory subsystem is unknown. Every RAG / vector-DB / MemGPT / Chroma-FAISS statement in this cluster traces to clone projects (AIRI's DuckDB-WASM + pglite "Memory Alaya", Open-LLM-VTuber, kimjammer) or to AI-generated aggregator text, never to Vedal.

## Summary B (skeptic)
The load-bearing claim of this cluster — that Neuro-sama has "within-session context only, no confirmed persistent cross-session memory" — is refuted at T1. In the 9/10 June 2025 dev stream Vedal says verbatim: "changes to the long-term and short-term memory of you. So the idea is theoretically you shouldn't forget anything that happens in a stream more or less. And also long-term you should be better at remembering important things and keeping that information for longer. And this system comes with lower latency," and that what he is testing is "her ability to remember what happens in a stream, what happens over multiple streams." A discrete long-term memory *store* (not fine-tuned weights) is further evidenced at T4 by NamuWiki's footnote quoting Vedal that Evil Neuro "currently only has three long-term memories," one occupied by "AI wanting to come out into reality," with expansion planned (~Nov 2024), and by virtualyoutuber.fandom stating Evil received "her own voice, model, personality, and memory bank" — which also refutes the claim that no source addresses whether Evil shares Neuro's memory. What is genuinely established is therefore: a runtime, per-character, long-term + short-term memory subsystem exists and is shipped; it was small and slot-like in late 2024; it was rebuilt/extended in mid-2025 with lower latency; and Vedal himself calls it experimental and testable only by streaming. What remains unknown at every tier is the *mechanism*: no primary or official source names RAG, a vector database, summarisation, embeddings, slot count for Neuro herself, retrain cadence, catastrophic-forgetting handling, or any end-of-stream consolidation step — the "RAG 2.0 / vector databases" line circulating in search-engine AI summaries traces only to a Medium essay and to clone stacks (AIRI's DuckDB-WASM/pglite/"Memory Alaya", Open-LLM-VTuber's removed LTM/Mem0), never to Vedal. Two widely repeated colour items in this cluster are misattributed: the "inconsistency of her memory" and "calling him a mosquito / repeating insults months ago" quotes are not present on the Fandom pages cited (verified by direct page read today), and the "Vedal runs Neuro overnight ... helps train her" quote is not in the English Wikipedia article, which instead states "Neuro-sama does not stream 24/7." Finally, date discipline: the Mar–Jun 2026 rewrite and the May 2026 server are about Unity *RAM* memory leaks and hardware, not cognitive memory — Vedal never mentions the memory subsystem in any rewrite quote, and the September 2026 "big announcement" turned out to be the 19 Dec 2026 Los Angeles live concert, so nothing newer than June 2025 is publicly known about how Neuro's memory works.

## Contradictions resolved
- Contradiction #3 (memory: 'irregular offline fine-tuning only' vs discrete dated memory upgrades) — RESOLVED in favour of the runtime-memory reading. Vedal's 9/10 June 2025 dev-stream transcript describes a long-term/short-term memory system he built, swapped in, had 'never tried before', and which 'comes with lower latency' — properties of a runtime component, not of fine-tuned weights. NamuWiki's report of Vedal saying Evil Neuro's long-term memory held three countable items with expansion planned points the same way. Offline fine-tuning is real but is a separate mechanism (and its documented origin, per Vedal's Kotaku interview, was bias/safety curation, not memory). The fine-tuning-only explanation should be dropped from the report as the account of long-term memory.
- Clone-contamination flag #2 (RAG / vector DB / MemGPT in angles 01, 03, 04, 09) — RESOLVED as contamination plus search-summary noise. No T1 or T2 source mentions retrieval, embeddings or a database; the neuro-sdk spec's only retention concept is the `ephemeral_context` flag. The 'indications of RAG-like retrieval' phrasing is one community author's flagged speculation, and the stronger 'RAG 2.0 / vector databases' assertion regenerates from a search engine summarising a Medium op-ed. MemGPT belongs to Open-LLM-VTuber (whose README no longer even ships long-term memory); PGVector/DuckDB belong to AIRI. None may be attributed to Neuro.
- Clone-contamination flag #8 ('~2B parameters, q2_k') — RESOLVED as unverified lore, provenance identified. The April 2026 audit traces the numbers to Fandom wikis only, and the originating bullet on virtualyoutuber.fandom attributes it to Vedal with no adjacent footnote. Report it as circulating lore with a named origin, never as a spec.

- Contradiction #3 (Memory: fine-tuning-only explanation vs. dated, failing memory upgrades) — RESOLVED IN FAVOUR OF A RUNTIME MEMORY COMPONENT. Vedal's own June 2025 transcript describes a 'system' for long-term and short-term memory with its own latency profile, tells Neuro she may choose what to remember, and defines the test as recall across multiple streams. NamuWiki's Vedal-attributed footnote (Evil has exactly three long-term memories, expandable) and virtualyoutuber.fandom's 'memory bank' independently describe a discrete store. The 'irregular offline fine-tuning explains apparent long-term memory' model is a community doc's inference built from sources that never included dev-stream transcripts, and it is refuted. Fine-tuning/curation is real but is a separate, safety-motivated pipeline (Wikipedia, post-Jan-2023 ban), not the memory mechanism.
- Clone-contamination flag #2 (RAG / vector DB / MemGPT as 'possible but undocumented RAG-like retrieval') — UPHELD AND SHARPENED. The 'RAG 2.0 / vector databases' assertion that appears in search-engine AI summaries traces to a Medium essay with no primary citation, and Grokipedia itself declines to name any vector DB or RAG. Report: long-term memory exists (Vedal, T1); its mechanism is unknown; RAG/vector-DB framing must be labelled clone-derived speculation.
- Clone-contamination flag #3 (32k context window) — UPHELD. The only Vedal-sourced context signal is that he tested a 'longer context length' as part of an intelligence upgrade (June 2025, no number). The 32k figure is a clone config and must never be attributed to Neuro.

- Contradiction #6 (the four colliding 'V3' labels) — PARTIALLY RESOLVED for this cluster.
